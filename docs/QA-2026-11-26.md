# Website QA — 26 November 2026

Website: https://spicy-banikhet.netlify.app/

Audited production code: `41010fd` (Netlify deploy `6b07afbc64183e9b37b42b68`).

## Scope and evidence

Live browser inspection used the in-app Chromium browser. Viewports tested:

| Device group | CSS viewport sizes |
| --- | --- |
| Phones | 320×568, 360×640, 390×844, 430×932 |
| Landscape phone | 667×375 |
| Tablets | 768×1024, 820×1180 |
| Laptops | 1024×768, 1280×500, 1366×768, 1440×900 |
| Desktop | 1920×1080 |

Checks included page width, heading overflow, pinned scene height, forward/reverse thali progress, menu navigation and category highlighting, loaded images, keyboard skip navigation, contact-link targets, Google Maps embed loading, local references, response status, SEO metadata, and representative text contrast.

## Fixed during this audit

1. The active mobile menu category could be outside the visible horizontal navigation strip. It now scrolls horizontally into view when the active category changes, without changing page scroll or keyboard focus.
2. Hero image `sizes` underestimated the mobile plate width. It now reflects the overlapping composition so high-density phones can select an adequate image size.
3. The keyboard skip target had no explicit focus destination. The main element now accepts programmatic focus without adding a normal tab stop.
4. The home page lacked a canonical URL and a social preview image. Canonical, Open Graph, and Twitter card metadata now point to the current public site and a real storefront photograph.
5. `robots.txt` returned 404 and no sitemap existed. Both are now provided, with only the canonical homepage listed.
6. The README still described GitHub Pages publication and outdated image files. It now describes Netlify publication, the current image assets, and regression checks.

## Passed checks

- All 12 tested viewport sizes had document width equal to viewport width; no heading text exceeded its own box.
- The thali scene fitted the viewport at tested portrait-phone, tablet, laptop, and desktop sizes. The short landscape-phone layout intentionally uses a complete, unpinned thali.
- Forward and reverse scroll animation worked in the live browser.
- Menu links reached their matching sections below the sticky navigation. After the fix, the active Drinks tab stayed inside the visible mobile navigation area while the page scrolled.
- The homepage and 21 linked assets/crawler files returned HTTP 200. Asset bytes matched the committed source, including images, fonts, stylesheet, script, favicon, robots.txt and sitemap.xml.
- Loaded images had valid natural dimensions; all content images have alt text or an appropriate decorative treatment.
- A single H1 and unique element IDs were present; all internal fragment targets existed.
- Skip navigation explicitly focused MAIN after the fix; the next tab stop was Explore Menu.
- The old `/our-thali` URL redirected to the homepage thali section.
- The phone link used `tel:+919816161282`. Directions used the restaurant's existing coordinates. The map endpoint returned HTTP 200 and the embedded map rendered.
- Representative normal-text colour pairs had contrast ratios of at least 6.32:1. This was a token-level contrast check, not an exhaustive accessibility certification.
- Ten Node regression checks passed. These simulate reduced-motion, data-saving, oversized-content and compact-screen modes, preference changes, sequential animation and reversal, requestAnimationFrame scheduling, offscreen-write suppression, and menu visibility.

## Limits

- Tested in Chromium with responsive viewports, not on physical iOS/Android devices or in Safari/Firefox.
- Reduced-motion and data-saving modes were covered by JavaScript regression checks; system accessibility preferences were not changed.
- The no-JavaScript fallback was reviewed in HTML/CSS: all food layers are visible until JavaScript enables animation. A separate browser session with JavaScript disabled was not available.
- External Maps navigation and dialler links were inspected without initiating a phone call or a route session.
- The browser captured a MutationObserver error without a source URL at setup and on several reloads. Website source and the inspected Netlify HUD loader contain no MutationObserver. No site-script exception was identified, but the console error remains untraced and cannot be declared resolved.
- No Lighthouse/Core Web Vitals score, slow-network simulation, search indexing result, or third-party social-preview cache result is claimed.

## Recommended next steps

1. Replace illustrative dishes with consistent photographs of the restaurant's actual food. Keep the current transparent edges and responsive sizes.
2. Add useful menu details such as portion size and confirmed spice/allergen information. Do not infer dietary guarantees or publish prices until the owner approves them.
3. Add Restaurant structured data and keep name, address, phone and opening hours aligned with the Google Business Profile. Submit the sitemap through an owner-controlled Search Console account.
4. Connect a custom domain when ready, then update canonical and sharing URLs together.
5. If the restaurant accepts WhatsApp enquiries or advance orders, add a clear enquiry action using a confirmed WhatsApp number and explain what guests can request.
6. Add privacy-conscious measurement of menu, directions, and call clicks if the owner wants to evaluate how visitors use the site.
